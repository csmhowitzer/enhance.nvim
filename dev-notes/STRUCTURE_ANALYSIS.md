## 6-AC Plugin Standards (6 Chaos Orbs Each)

### 1. README.md ✅
**Format**: auto_cwd.nvim style
- Clear feature list with emojis
- Installation instructions (lazy.nvim local plugin)
- Configuration options table
- Usage examples
- Commands documentation
- Health check mention

### 2. Test Suite ✅
**Requirements**:
- Plenary/Busted framework
- `tests/minimal_init.lua` for test setup
- Flat structure: `tests/*_spec.lua` (NOT nested directories)
- Expose internal functions: `M._function_name` pattern
- Focus on behavior, not coverage

### 3. Lua Annotations ✅
**Requirements**:
- Complete type definitions
- `---@param` for all parameters
- `---@return` for return values
- `---@class` for custom types
- `---@field` for class properties

### 4. User Configuration ✅
**Requirements**:
- `setup()` function with overridable defaults
- Separate config module (e.g., `lua/enhance/config.lua`)
- Merge user options with defaults
- Validate configuration

### 5. Health Check ✅
**Requirements**:
- `lua/enhance/health.lua` module
- Auto-discovered by Neovim (no manual registration)
- Follow m_augment/wsl2_roslyn patterns
- Check: core functionality, configurations, commands, current state

### 6. Help Documentation ✅
**Requirements**:
- `doc/enhance.txt` file
- Folke's snacks.nvim style
- `{opts}` pattern for parameters
- Left-aligned code blocks with `>lua`, `>sh`, `>vim`
- Searchable tags
- Commands in table format (Lazy.nvim style)

## Gaps Identified in Onboarding Documentation

### ✅ Well Documented:

- Testing pattern (`M._function_name`) documented
- Plugin structure template provided

- Help documentation style specified

### ⚠️ Could Be Clearer:

2. **.gitignore patterns**: What to ignore in plugin repos
3. **Test fixtures**: Where to put test data files (like scratch-manager's `testft/`)

### 💡 Recommendation:
Add to `code_patterns.md`:

```markdown
### Development Artifacts
**Planning docs, test logs, demo scripts**: Store in `dev-notes/` directory

**.gitignore**: Always ignore `*.log`, `test_*.lua`, `demo_*.lua`
```
